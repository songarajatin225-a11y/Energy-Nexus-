# Energy Nexus — repo guide

Read this before exploring; it exists so a session does not re-derive the codebase.

## Two independent projects

**1. Energy Nexus OS** (repo root) — static industrial energy platform prototype.
No framework, no build step. Open `index.html` through a web server (`python3 -m
http.server`); `file://` breaks the JSON fetches.

- 21 screens, flat at root. `index.html` is the marketing landing; everything
  else is the product.
- The landing hero is a scroll-tied video scene (`js/hero-scroll.js`,
  `css/hero-scroll.css`): a 300vh track with a sticky viewport. Scroll drives
  `video.currentTime` through an exponential lerp — the clip is never played.
  Approved hero copy is split across three stages that fade sequentially. If the
  remote clip fails to load, the scene falls back to the ink ground and holds
  white type; never assume the video is available.
- `css/` theme · main · components · dashboard · charts · landing · responsive.
  `theme.css` holds every design token — colour, radius, spacing, elevation.
  Retune tokens rather than editing screens.
- `js/app.js` is the shell: sidebar, topbar, theme, demo clock, state,
  toast/modal/drawer, `ENX.auth`, `ENX.palette` (⌘K), `ENX.tables`, `ENX.report`.
- `js/charts.js` is a hand-built SVG chart engine. No chart library, do not add one.
- `js/data.js` loads `data/*.json`. All data is generated by
  `node tools/generate-data.js` — deterministic, seeded. Edit the generator, never
  the JSON.
- Page contract: each HTML ships a thin `<main>`; `app.js` wraps it in the shell,
  then fires `enx:ready`. Page modules listen for that. Also `enx:tick` (demo),
  `enx:sitechange`, `enx:theme`, `enx:loading`.

**2. `scroll-video/`** — separate Vite + React 18 + TS + Tailwind app. A single
scroll-tied video scene. `npm install && npm run dev`. Unrelated to the OS; do
not merge their styles or tooling.

## Rules that already cost a rewrite once

- **Sign-in is a demo gate, not security.** Client-side only, bypassable, and
  every file in `data/` is public regardless. Never describe it as protection.
- **Landing copy is content-locked.** Layout may change; wording, links and
  numbers may not.
- Simulated data must stay labelled. Future capability is marked `SIMULATION`,
  `PILOT` or `REGULATION DEPENDENT`.
- Diesel dispatch and regulated transactions are permanently human at every
  autonomy tier. This is modelled in the data, not just the copy.
- Carrier colours (grid, solar, BESS, DG…) mean data. `--accent-ui` means chrome.
  Do not cross them.

## Verifying

Playwright + the pre-installed Chromium at
`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`. Check console errors,
accessibility, and overflow at 320/375/390/768/1024/1440/1920 before claiming a
UI change works. `scroll-behavior: smooth` is set, so use
`scrollTo({behavior:'instant'})` in tests or you will sample mid-animation.
